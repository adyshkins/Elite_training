# Словарь для первого занятия

[К описанию курса](../README.md) · [К первой практике](../practices/01-introduction/README.md)

Не нужно заучивать определения. Возвращайтесь к ним, когда встречается незнакомое слово.

| Термин | Объяснение на примере нашей работы |
|---|---|
| Язык программирования | Правила, по которым мы записываем программу. В курсе используем Go. |
| Исходный код | Текст программы, который пишем и сохраняем в файле. |
| Файл `main.go` | Текстовый файл с кодом Go; `.go` — расширение имени файла. |
| Папка проекта | Обычная папка на компьютере с файлами одной работы. Сначала создаём папку, затем открываем её в редакторе. |
| Редактор кода | Программа для создания и изменения исходных файлов. Наш вариант — Visual Studio Code, или VS Code. |
| IDE | Среда разработки, объединяющая редактор и другие инструменты. Пример — GoLand. |
| Go SDK | Инструменты Go, необходимые для запуска и сборки кода. Редактор не заменяет SDK. |
| Компиляция, или сборка | Преобразование исходного кода в исполняемую программу. Ошибки в коде могут помешать сборке. |
| Терминал | Область окна для ввода команд и чтения результата; открывается в VS Code через **Terminal → New Terminal**. |
| Команда | Строка для инструмента, например `go version`. Её вводят в терминале и выполняют клавишей Enter, а не вставляют в `main.go`. |
| Текущая папка | Папка, относительно которой терминал выполняет команды. Её проверяем через `pwd`. |
| Модуль Go | Группа пакетов с общим `go.mod`. В первой работе создаём один модуль своего проекта. |
| `go.mod` | Служебный текстовый файл с именем модуля и версией Go; позже в нём появятся зависимости. Код программы пишем не в нём. |
| Пакет | Способ группировки кода Go. Для исполняемой программы используем `package main`. |
| Функция | Именованный фрагмент программы. Наш код начинается с функции `main`. |
| Переменная | Именованное значение, например `completed := 1`; далее его можно изменить. |
| Константа | Значение с именем, которому далее нельзя присвоить другое значение. |
| Git | Инструмент сохранения истории проекта. Работает локально и без GitHub. |
| Репозиторий Git | Папка проекта с историей изменений в скрытой служебной папке `.git`. |
| Коммит, commit | Запись выбранных изменений в локальную историю с поясняющим сообщением. Она сама по себе не отправляет код в интернет. |
| GitHub | Сайт для размещения репозиториев. Git и GitHub — разные вещи. |
| Push | Отправка локальных коммитов в удалённый репозиторий, например на GitHub. |
| Clone | Получение локальной копии репозитория вместе с историей. Для чтения первой практики не требуется. |
| README | Файл с описанием проекта. GitHub показывает `README.md` под списком файлов. |
| Markdown | Простая текстовая разметка заголовков, ссылок и блоков кода; инструкции курса написаны в ней. |
| `.gitignore` | Список исключений для добавления файлов в Git. Он не удаляет уже опубликованные данные. |

## Три разных действия

**Сохранить файл** — записать изменения на диск: **Ctrl+S**, на macOS — **Cmd+S**.

**Сделать коммит** — записать выбранные изменения в историю Git на компьютере.

**Отправить изменения** — загрузить коммиты на GitHub. После обычного сохранения файла сайт автоматически не обновляется.

Источники для продолжения: [начало работы с Go](https://go.dev/doc/tutorial/getting-started), [терминал VS Code](https://code.visualstudio.com/docs/terminal/basics), [Git в VS Code](https://code.visualstudio.com/docs/sourcecontrol/quickstart).
