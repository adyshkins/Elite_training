# Выполнение и сдача практических работ

[К описанию курса](../README.md) · [Первая публикация на GitHub](first-project-github.md)

## Что считать выполненной работой

Выполните обязательные задания, проверьте указанные наборы данных и подготовьте исходный код. Дополнительные упражнения не заменяют обязательные и выполняются после основной части.

На демонстрации нужно запустить программу, объяснить её устройство и ответить на вопросы по использованным конструкциям. Готовый пример из учебного репозитория сам по себе не является решением самостоятельного задания.

В первой практике различаем **результат за 90 минут в аудитории** и **полный результат к сдаче**. На занятии устанавливаем Go и VS Code, создаём проект, запускаем и собираем первую программу, разбираем синтаксис и пишем карточку. **Самостоятельно обязательно:** установить Git, опубликовать проект на GitHub с двумя коммитами и выполнить конвертер минут с проверками. Если установка заняла больше времени, незавершённый пункт из аудиторной части тоже выполняется после пары. Конкретный срок сдачи сообщает преподаватель. [Порядок работы по этапам](../practices/01-introduction/README.md#порядок-работы) · [Чек-лист ПР № 1](../practices/01-introduction/README.md#9-проверка-и-сдача).

## Где хранить решения

Учебный репозиторий содержит материалы преподавателя. Собственный код храните в отдельной папке. В первой работе это **`GoProjects/go-practice-01`**; папки карточки и конвертера находятся внутри неё и используют общий `go.mod`.

С первой работы учимся сохранять историю Git и публиковать проект в **своём аккаунте GitHub**. Отправлять решения в `adyshkins/Elite_training` через коммиты или pull request не нужно. Инструкция по шагам: [установка Git и первая публикация](first-project-github.md).

Передайте преподавателю **адрес вашего репозитория из адресной строки браузера**, а не путь `C:\...` на компьютере и не ссылку на курс. Канал передачи ссылки определяется на занятии; отдельная система сдачи здесь не вводится.

Для **Private**-репозитория одной ссылки недостаточно: предоставьте преподавателю доступ и убедитесь, что приглашение принято. Для **Public** проверьте, что опубликован только учебный код с вымышленными данными.

## Когда допустим архив

Если GitHub временно недоступен или возникла техническая проблема, покажите локальные файлы, запуск и доступную историю Git. Согласуйте с преподавателем временную передачу ZIP с исходниками. После устранения проблемы завершите публикацию; архив не заменяет освоение Git в первой работе.

Архив должен содержать исходные `.go`-файлы, `go.mod`, README и, когда появятся зависимости, `go.sum`. Не включайте `.git`, исполняемые файлы, токены и персональные данные. Не удаляйте `.git` из рабочего проекта ради архива: подготовьте отдельную копию исходников.

## Состав репозитория

В репозитории должны быть исходники, `go.mod`, при наличии зависимостей — `go.sum`, `.gitignore` и понятный README. Исполняемые файлы, временные файлы и личные настройки редактора не нужны.

Не публикуйте пароли, токены, `.env` с настоящими значениями, чужие персональные данные и рабочие базы. Используйте вымышленные примеры. Сам по себе `.gitignore` не очищает уже созданную историю.

Для README используйте [готовый шаблон](../practices/01-introduction/templates/project-readme.md). Его нужно сохранить как **`README.md` в корне своего проекта**, заменить подсказки своими данными и обновлять после заданий.

В описании нужны система, версия Go, выполненные пункты, команды запуска и проверенные данные. Например, после выполнения карточки и конвертера из корня проекта должны работать:

```text
go run .
go run ./cmd/card
go run ./cmd/time-converter
```

Не пишите, что задача выполнена, если она пока не работает. При использовании заготовки поясните, что добавили самостоятельно.

Отдельный многостраничный отчёт Word не требуется. Скриншоты могут дополнить результат, но не заменяют исходники и команды запуска.

## Перед сдачей

Сохраните файлы, затем в терминале папки своего проекта выполните:

```text
go fmt ./...
go build ./...
```

Проверьте все наборы данных из задания. Создайте коммит, отправьте его на GitHub и откройте сайт: там должны быть **последние изменения**, а не первая версия. Запуск проекта не должен зависеть от личных файлов или секретов.

Критерии конкретной практики имеют приоритет над общими правилами.

## Исправления и пропуски

Исправляйте своё решение, не подменяя его готовым примером. Пропущенную тему восстановите по инструкции и примерам. Стартовый код следующей работы используйте, только если он опубликован в её папке.

При ошибке сообщите номер практики, шаг, команду, текущую папку и текст ошибки целиком. Пароли и коды входа не присылайте.
