# Первый проект в Git и на GitHub — пошаговая инструкция

[К первой практике](../practices/01-introduction/README.md) · [К описанию курса](../README.md)

## С чего начинаем

У вас уже открыт **свой** проект `go-practice-01` в VS Code. В нём есть `main.go` и `go.mod`, команда `go run .` выводит приветствие. Если этого пока нет, сначала выполните [создание первой программы](../practices/01-introduction/README.md#2-создаём-проект).

На этом этапе **не создаём новый Go-проект** и не публикуем папку `Elite_training`. Продолжаем работать с той же своей папкой.

**Git** сохраняет историю изменений на компьютере. **GitHub** — сайт, на котором можно разместить репозиторий. Мы сначала создадим локальную историю, затем загрузим её в свой аккаунт. Наличие GitHub-аккаунта само по себе не означает, что на компьютере установлен Git.

Для основного пути нужны VS Code, Git и браузер. GitHub Desktop, GitHub CLI, SSH-ключи и токены вручную не настраиваем. Вход при публикации выполним через встроенную поддержку GitHub в VS Code.

## Шаг 1. Установите Git

### Windows

1. Откройте [официальную страницу установки Git](https://git-scm.com/install/) и выберите **Windows**.
2. Скачайте обычный установщик под архитектуру компьютера, не исходный код. Откройте его из «Загрузок».
3. Пройдите мастер установки. На экране выбора редактора можно выбрать **Visual Studio Code**, если он уже установлен. Остальные параметры оставляйте стандартными, если преподаватель не указал иное.
4. На экране настройки доступности команд оставьте вариант **Git from the command line and also from 3rd-party software**. Он позволяет использовать Git из терминала VS Code.
5. Завершите установку. При отсутствии нужных прав обратитесь к преподавателю.
6. Полностью закройте и заново откройте VS Code, затем откройте свою папку `go-practice-01` и **Terminal → New Terminal**.

### macOS

Откройте терминал VS Code и выполните `git --version`. Если система предложит установить **Command Line Developer Tools**, завершите эту установку и откройте терминал заново. Альтернативные способы приведены на [официальной странице Git для macOS](https://git-scm.com/install/mac). На учебном компьютере установку согласуйте с преподавателем.

### Linux

Проверьте `git --version`. Если Git отсутствует, используйте [официальные инструкции для своего дистрибутива](https://git-scm.com/install/linux) с преподавателем или администратором. Не копируйте команды установки Windows в Linux.

### Проверка для всех систем

**В терминале VS Code:**

```text
git --version
```

В ответе должны быть слова `git version` и номер выпуска. Если команда не найдена, сначала завершите установку и перезапустите редактор. Переходить к `git init` пока рано.

## Шаг 2. Создайте аккаунт GitHub

1. В браузере откройте [GitHub](https://github.com/). Если аккаунт уже есть, нажмите **Sign in** и войдите. Второй аккаунт для работы создавать не нужно.
2. Для регистрации выберите **Sign up**. Заполните поля по подсказкам: доступная вам почта, пароль и уникальное имя пользователя. Запомните имя пользователя: оно будет в адресе вашего репозитория.
3. Пройдите проверку и подтверждение почты. Если сервис запросит дополнительную проверку, выполните её самостоятельно. Пароль, коды и резервные коды преподавателю или одногруппникам не передавайте.
4. После входа убедитесь, что открыт именно ваш аккаунт. Для наших учебных операций не требуется оформлять платную подписку.

[Официальная инструкция регистрации](https://docs.github.com/en/account-and-profile/how-tos/account-management/creating-an-account-on-github).

**Подготовьте адрес автора коммитов:** откройте [GitHub → Settings → Emails](https://github.com/settings/emails). Для сохранения приватности почты включите **Keep my email addresses private**, если настройка выключена, и скопируйте показанный GitHub адрес **`noreply`**. Его точный вид берите со своей страницы — не придумывайте и не копируйте адрес другого человека. Подробнее: [адрес автора коммитов](https://docs.github.com/en/account-and-profile/how-tos/email-preferences/setting-your-commit-email-address).

Новый репозиторий на сайте **пока не создавайте**: ниже его создаст VS Code при публикации.

## Шаг 3. Включите Git в своём проекте

Вернитесь в VS Code. В терминале выполните:

```text
pwd
ls
```

Путь должен заканчиваться на `go-practice-01`, среди файлов должны быть `main.go` и `go.mod`. **Не запускайте следующую команду в «Документах», папке всех проектов или материалах преподавателя.**

**Команда для терминала проекта:**

```text
git init -b main
```

Git создаст скрытую служебную папку `.git` и основную ветку `main`. Ветка — отдельная линия истории; сейчас используем только одну. На GitHub пока ничего не отправлено.

Не удаляйте `.git`: в ней хранится история. Если проект уже был Git-репозиторием, повторная инициализация не нужна; проверьте `git status` и продолжите с настройки автора.

## Шаг 4. Укажите автора локальных коммитов

В следующих двух командах **замените значения внутри кавычек**. Вместо `YOUR_GITHUB_USERNAME` укажите своё имя пользователя или выбранное имя автора; вместо `YOUR_NOREPLY_EMAIL` вставьте свой адрес из Settings → Emails. Это не пароль.

```text
git config user.name "YOUR_GITHUB_USERNAME"
git config user.email "YOUR_NOREPLY_EMAIL"
```

Пример только для поля имени: `git config user.name "student-go"`. Не используйте имя преподавателя.

Мы намеренно не добавляем `--global`: эти настройки действуют **только для текущего проекта**, что удобно на учебном компьютере. Имя и адрес автора могут быть видны в опубликованной истории.

**Проверка:**

```text
git config user.name
git config user.email
```

Команды должны показать ваши выбранные значения, а не текст-заглушку. Не выводите и не передавайте кому-либо токены доступа.

## Шаг 5. Подготовьте README и .gitignore

В корне **`go-practice-01`**, рядом с `main.go` и `go.mod`, создайте два обычных текстовых файла через левую панель VS Code → **New File**.

### Файл `.gitignore`

Имя начинается с точки; пишите его точно, без `.txt` в конце. Откройте [готовое содержимое `.gitignore`](../practices/01-introduction/templates/.gitignore), скопируйте **текст внутри файла** в свой `.gitignore` и сохраните.

Этот файл исключает из будущего добавления в Git исполняемые файлы, локальные настройки и секреты. Он **не удаляет из истории то, что уже было опубликовано**.

### Файл `README.md`

Скопируйте [шаблон описания проекта](../practices/01-introduction/templates/project-readme.md) в свой `README.md`. Заполните систему, версию Go, выполненные пункты и команды реально существующих программ. Версию узнайте через `go version`.

Markdown — обычный текст с простой разметкой: `#` обозначает заголовок, обратные кавычки выделяют код. Для просмотра оформления используйте **Ctrl+Shift+V** в Windows/Linux или **Cmd+Shift+V** в macOS, когда открыт README. Отдельную программу для Markdown устанавливать не нужно.

После сохранения в проекте должны быть как минимум:

```text
go-practice-01/
├── .gitignore
├── README.md
├── go.mod
└── main.go
```

Если вы уже создали программы в `cmd`, они тоже остаются здесь. `hello.exe`, `hello`, а также результат сборки по имени модуля — `go-practice-01` или `go-practice-01.exe` — могут оставаться на диске, но в Git добавляться не должны. Они предусмотрены в шаблоне исключений.

## Шаг 6. Создайте первый коммит

Сначала проверьте код:

```text
go fmt ./...
go build ./...
```

Исправьте ошибки, если они есть. Затем посмотрите, что видит Git:

```text
git status --short
```

У новых файлов обычно стоит `??`: Git видит их, но ещё не включил в историю. Среди них должны быть ваш код, `go.mod`, README и `.gitignore`. Исполняемых файлов и настоящих секретов быть не должно.

**Добавьте файлы в подготовку коммита и ещё раз проверьте список:**

```text
git add .
git status
git diff --cached --name-only
```

`git add .` подготавливает изменения текущей папки с учётом `.gitignore`, но **ещё не создаёт коммит**. Последняя команда показывает имена файлов, которые попадут в него.

Если обнаружили лишний или секретный файл, не выполняйте следующий шаг: покажите ситуацию преподавателю, уберите файл из подготовленных изменений и настройте исключения. Не отправляйте секреты, чтобы «потом удалить».

**Теперь сохраните подготовленное в истории:**

```text
git commit -m "Добавить первую программу на Go"
```

`-m` задаёт сообщение коммита. Оно коротко объясняет изменение. **Коммит локальный: сайт GitHub ещё не обновился.**

**Проверка:**

```text
git log -1 --oneline
git status
```

Первая команда должна показать запись с вашим сообщением, вторая — отсутствие несохранённых в коммит изменений (`working tree clean`), если после коммита вы ничего не меняли.

## Шаг 7. Опубликуйте через VS Code

1. В VS Code оставьте открытым свой проект `go-practice-01`.
2. Откройте **View → Command Palette / Вид → Палитра команд**. Клавиши: **Ctrl+Shift+P** в Windows/Linux, **Cmd+Shift+P** в macOS. Это поле команд **редактора**, не терминал.
3. В поиске палитры введите **`Publish to GitHub`** и выберите команду публикации. Если её нет, см. таблицу проблем ниже.
4. При запросе входа разрешите VS Code открыть браузер. Проверьте адрес `github.com` и свой аккаунт, прочитайте запрос авторизации VS Code, подтвердите вход и вернитесь в редактор. Если браузер предложит открыть Visual Studio Code, подтвердите это действие.
5. Укажите свободное имя репозитория, например **`go-practice-01`**. Проверьте, что владельцем будет **ваш аккаунт**, а не преподаватель или организация.
6. Выберите доступ: **Public** — код виден всем; **Private** — доступ только у вас и приглашённых участников. Для учебного кода с вымышленными данными можно выбрать Public. Для Private позже пригласите преподавателя; одна ссылка доступа не даёт.
7. Если редактор дополнительно показывает список публикуемых файлов, проверьте его. Пароли, исполняемые файлы и личные данные туда не включайте.
8. После завершения откройте предложенную ссылку на GitHub. Если ссылка не появилась, в браузере откройте свой профиль → **Repositories** → `go-practice-01`.

Надписи интерфейса могут отличаться по языку редактора, поэтому в инструкции приведены английские имена команд. Последовательность публикации описана в [официальном руководстве VS Code](https://code.visualstudio.com/docs/sourcecontrol/quickstart), а вход — в [документации GitHub-интеграции](https://code.visualstudio.com/docs/sourcecontrol/github).

**Пример формы адреса, не ссылка на ваше решение:**

```text
https://github.com/YOUR_GITHUB_USERNAME/go-practice-01
```

В реальной ссылке должны быть ваше имя и выбранное имя репозитория. Имя модуля `example.com/go-practice-01` в `go.mod` для этого учебного исполняемого проекта менять не требуется. Организацию путей модулей разберём позднее.

### Проверка публикации

На сайте откройте `main.go` и убедитесь, что видите **свой** текст. Проверьте `go.mod`, README и сообщение первого коммита. Публикация сохраняет код на GitHub, но **не запускает программу как веб-сайт**.

## Шаг 8. Отправьте ещё одно изменение

1. В VS Code добавьте в README строку `Проверено: проект запускается локально.` и сохраните файл.
2. В терминале своего проекта выполните:

```text
git status --short
git add README.md
git commit -m "Уточнить инструкцию запуска"
```

3. В VS Code откройте **View → Source Control / Вид → Управление версиями**. В верхнем меню панели **… / More Actions** выберите **Push / Отправить**.
4. Обновите страницу репозитория в браузере. Новая строка и второй коммит должны стать видны.

Сейчас используем **Push**, а не **Sync Changes**: синхронизация дополнительно получает изменения с сервера. Подробно совместную работу разберём позже.

Когда добавите конвертер и другие файлы, повторите цикл: **сохранить → проверить код → `git add .` → проверить список → `git commit -m "..."` → Push → проверить GitHub**. Приглашение к вводу и многоточие из примера сообщения не копируйте: напишите сообщение о своём изменении.

## Если что-то не получилось

| Сообщение или ситуация | Что делать |
|---|---|
| `git` не найден | Проверьте установку, полностью перезапустите VS Code и создайте новый терминал |
| `not a git repository` | Проверьте `pwd`, откройте свою папку и выполните `git init -b main`, если Git в ней ещё не создавался |
| `Author identity unknown` | После `git init` выполните обе команды `git config` из шага 4 |
| `nothing to commit` | Сохраните изменённый файл, посмотрите `git status`; возможно, все изменения уже в коммите |
| `Publish to GitHub` отсутствует | Проверьте установленный Git, локальный проект и включённые встроенные компоненты Git/GitHub VS Code; обратитесь к преподавателю, не устанавливайте случайные расширения |
| Имя репозитория занято | Проверьте, не опубликовали ли вы эту работу раньше; существующий репозиторий не удаляйте |
| `403`, `Permission denied`, `Repository not found` | Проверьте аккаунт, выбранный репозиторий и доступ; в репозиторий преподавателя своё решение не отправляем |
| `rejected`, `non-fast-forward` | На сервере есть другая история. Остановитесь и разберите ситуацию с преподавателем. Не применяйте `--force` |
| Просят пароль или токен в терминале | Используйте описанный вход и отправку из VS Code. Не вставляйте пароль GitHub вместо токена и не отправляйте секреты в чат |
| В браузере старый код | Проверьте, сохранён ли файл, создан ли коммит и выполнен ли Push; затем обновите страницу |
| Преподаватель не видит Private-репозиторий | Пригласите его аккаунт через настройки доступа и дождитесь принятия приглашения |
| GitHub недоступен | Сохраните локальный проект и коммиты. Покажите их преподавателю, отправку завершите при восстановлении доступа |

На общем компьютере после работы выйдите из GitHub в браузере и из аккаунта GitHub в VS Code. Не оставляйте пароли и сессии другим пользователям. Дальнейшую работу безопаснее продолжать в своей системной учётной записи.

## Что показать преподавателю

Ссылку на собственный репозиторий, первый и следующий коммиты, исходные файлы без исполняемых результатов сборки и понятный README. Покажите, что умеете запустить проект **локально**.
