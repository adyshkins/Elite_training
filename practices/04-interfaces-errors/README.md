## 1. Интерфейс

Интерфейс задаёт набор операций независимо от способа хранения:

```go
type TaskStore interface {
    Add(title string, priority int) (Task, error)
    Get(id int) (Task, error)
    Complete(id int) error
    Delete(id int) error
    List() []Task
}
```

Если у `MemoryStore` есть все пять методов **с точно такими сигнатурами**, тип реализует интерфейс автоматически. Не нужно писать `implements`, как в некоторых других языках.

```go
type MemoryStore struct {
    tasks  []Task
    nextID int
}
func NewMemoryStore() *MemoryStore {
    return &MemoryStore{nextID: 1}
}
```

Методы меняют поля структуры, поэтому у них получатель `*MemoryStore`. В будущем реализацию в памяти можно будет заменить файловой или базой данных, сохранив тот же интерфейс.

## 2. Ошибки — обычные возвращаемые значения

```go
var (
    ErrNotFound = errors.New("задача не найдена")
    ErrInvalid  = errors.New("неверные данные задачи")
)

func (s *MemoryStore) Get(id int) (Task, error) {
    for _, task := range s.tasks {
        if task.ID == id {
            return task, nil
        }
    }
    return Task{}, fmt.Errorf("id %d: %w", id, ErrNotFound)
}
```

`nil` во втором результате означает отсутствие ошибки. `%w` оборачивает исходную ошибку дополнительной информацией. Проверять её следует через `errors.Is`, а не сравнением текстов.

```go
task, err := store.Get(99)
if errors.Is(err, ErrNotFound) {
    fmt.Println("Такой задачи нет")
} else if err != nil {
    fmt.Println("Ошибка:", err)
} else {
    fmt.Println(task.Title)
}
```

При ошибке не считайте `Task{}` найденной задачей. Всегда проверяйте `err` до обработки полезного результата.

## 3. CRUD в памяти

Для начала повторите модель из предыдущей работы в **новом** `main.go`:

```go
type Task struct {
    ID int
    Title string
    Status string
    Priority int
}
```

Пока мы не проходили пакеты, держать два независимых примера с `package main` в разных каталогах — нормально.

Методы `MemoryStore`:

1. `Add` — убрать пробелы по краям `strings.TrimSpace`, отклонять пустое название и приоритет не из диапазона 1–3; создавать `Task` со статусом `new`, увеличивать `nextID` **только после успеха**.
2. `Get` — вернуть задачу по ID, иначе ошибку `ErrNotFound`, обёрнутую через `%w`.
3. `Complete` — изменить `s.tasks[i].Status` на `done`; при отсутствии ID вернуть ошибку. Повторное завершение уже завершённой задачи допустимо.
4. `Delete` — удалить из среза по индексу, при отсутствии ID вернуть ошибку. Удалённый ID повторно не выдаётся.
5. `List` — вернуть **копию** внутреннего среза.

Важный нюанс: срез содержит ссылку на базовый массив. Если вернуть `s.tasks` напрямую, вызывающий код сможет менять внутренние объекты хранилища:

```go
func (s *MemoryStore) List() []Task {
    return append([]Task(nil), s.tasks...)
}
```

## 4. Консольное меню

Для ввода используем один `bufio.Scanner`, строки преобразуем в целые числа через `strconv.Atoi`. Прежде чем вызвать метод хранилища, проверяем ошибку преобразования.

Команды:
- `1` — добавить задачу (прочитать название и приоритет).
- `2` — показать список.
- `3` — завершить задачу по ID.
- `4` — удалить задачу по ID.
- `0` — выход.

Неверный ввод не должен завершать программу. В каркасе уже есть `readLine`, цикл и `switch`, но сами методы хранилища нужно написать самостоятельно.

```go
scanner := bufio.NewScanner(os.Stdin)
line, ok := readLine(scanner, "Команда: ")
if !ok {
    return // EOF: ввод завершён
}
fmt.Println(line)
```

Если пользователь нажал Ctrl+D/Ctrl+Z и ввод завершился, корректно закончите работу. При необходимости после выхода проверяйте `scanner.Err()`.

## 5. defer

```go
func run(store TaskStore, scanner *bufio.Scanner) {
    defer fmt.Println("Работа приложения завершена")
    // цикл обработки команд
}
```

`defer` выполняется **при выходе из функции**, а не в конце каждой итерации. Несколько вызовов `defer` выполняются в обратном порядке регистрации. При `os.Exit` отложенные вызовы не выполняются.

## Типичные ошибки

| Проблема | Причина |
|---|---|
| Не реализован интерфейс | Не совпадает сигнатура одного из пяти методов |
| Не меняется статус | Изменяется копия `task` из `range`, а не `s.tasks[i]` |
| Принимается пустое название | Забыли `strings.TrimSpace` |
| Программа падает на неверном ID | Вместо обращения по индексу нужно вернуть `ErrNotFound` |
| `strconv.Atoi` даёт ошибку | Нужна проверка `err` |
| Повторно выдан удалённый ID | Нельзя пересчитывать ID по длине среза |
| Непредсказуемый ввод | Используйте один `Scanner` |
