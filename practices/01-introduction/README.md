# Практическая работа № 1. Знакомство с Go: от первой программы до GitHub

[К описанию курса](../../README.md) · [Следующая практика →](../02-control-flow-functions/README.md)

**Курс:** «Бэкенд-разработка на языке Go»

**Формат:** одна пара, 90 минут, и самостоятельное закрепление

**Статус:** полное задание

## Что вы сделаете

Вы установите Go и редактор, сами создадите папку проекта и файл программы, запустите код, разберёте базовый синтаксис и опубликуете свою работу на GitHub. Знать Go, терминал, Git или уметь настраивать редактор заранее **не требуется**.

Главный результат первой встречи — вы понимаете, **где лежит ваш код, как его изменить, сохранить, запустить и отправить в свой репозиторий**. Конвертер с вводом данных закрепляет тему после основного маршрута; его условие и проверки сохранены в самостоятельной части.

> **Впервые открыли GitHub?** Прочитайте [как пользоваться страницей курса и получать файлы](../../docs/how-to-use.md). Для чтения материалов аккаунт не нужен. Первую программу создаём сами; скачивать весь курс необязательно.

## Порядок работы

| Этап | Где работать | Результат |
|---|---|---|
| 1. Инструменты | Браузер, установщик, VS Code | Работает `go version` |
| 2. Свой проект | Файловый менеджер и VS Code | Есть папка и `go.mod` |
| 3. Первая программа | Файл `main.go` и терминал | Приветствие в терминале |
| 4. Сборка | Терминал | Запускается исполняемый файл |
| 5. Синтаксис и карточка | Отдельный файл в том же проекте | Программа с переменными и константой |
| 6. Первая публикация | Git, VS Code и браузер | Проект в вашем аккаунте GitHub |
| 7. Закрепление | Свой проект | Конвертер, проверки и обновление репозитория |

На паре идём по основному маршруту с преподавателем. Если установка или регистрация заняли значительную часть занятия, незавершённые шаги продолжаются самостоятельно по этой же инструкции. Установка не должна превращаться в гонку; не пропускайте проверку каждого этапа. До сдачи нужно завершить обязательные задания, перечисленные в конце.

## 1. Знакомимся с инструментами

**Go** — язык программирования: правила, по которым мы записываем программу. **Исходный код** — её текст. **Go SDK** предоставляет инструменты, которые проверяют и собирают этот текст в программу. **Редактор** нужен, чтобы создавать и изменять файлы.

Будем пользоваться **Visual Studio Code (VS Code)**. Другие варианты — GoLand, обычный редактор с терминалом, Go Playground в браузере. Обзор не означает, что нужно установить всё: основной путь курса один.

Выполните [пошаговую установку Go и VS Code](../../docs/environment.md), затем вернитесь сюда. Не устанавливайте PostgreSQL и веб-фреймворки. Git подключим после первой программы.

**Проверьте во встроенном терминале VS Code:**

```text
go version
```

Видите номер версии и название платформы? Можно продолжать. Сообщение «команда не найдена» сначала нужно исправить по инструкции установки.

## 2. Создаём проект

### Шаг 2.1. Создайте обычную папку

**В Windows:**

1. Нажмите **Win+E**: откроется Проводник.
2. Откройте «Документы». Нажмите правой кнопкой по свободному месту, выберите **Создать → Папку**, назовите её **`GoProjects`**.
3. Откройте `GoProjects`. Таким же способом создайте внутри папку **`go-practice-01`**.

Если `GoProjects` уже есть, используйте её. Если уже есть `go-practice-01` с вашей работой, сначала проверьте содержимое с преподавателем: не удаляйте и не заменяйте его.

**В macOS:** откройте Finder → «Документы» и создайте такие же две папки через **File → New Folder**. **В Linux:** создайте их в доступной личной папке через файловый менеджер.

Получится:

```text
Документы/
└── GoProjects/
    └── go-practice-01/     ← наша пока пустая папка проекта
```

Это не команда и не программный код, а изображение расположения папок. Названия папок перепишите точно: дальше команды предполагают эту структуру.

### Шаг 2.2. Откройте созданную папку в VS Code

1. Переключитесь в VS Code.
2. Выберите **File → Open Folder / Файл → Открыть папку**.
3. Найдите созданную папку **`GoProjects/go-practice-01`**, выделите её и подтвердите выбор.
4. Если редактор спросит о доверии, подтвердите доверие **этой пустой папке, которую вы только что создали**. Не распространяйте это действие на чужие неизвестные проекты.
5. Слева в панели **Explorer / Проводник** должно быть название `GO-PRACTICE-01`. Если панель скрыта, выберите **View → Explorer / Вид → Проводник**.

Мы открываем именно `go-practice-01`, не «Документы», не весь `GoProjects` и не скачанный репозиторий преподавателя. Пока список файлов пустой — так и должно быть.

### Шаг 2.3. Откройте терминал проекта

Выберите **Terminal → New Terminal / Терминал → Создать терминал**. Щёлкните внутри нижней панели **TERMINAL**.

**В терминале выполните по одной строке, каждый раз нажимая Enter:**

```text
pwd
ls
```

`pwd` показывает **текущую папку**, `ls` — её содержимое. Эти команды подходят для выбранного PowerShell в Windows и для терминала macOS/Linux. Путь должен заканчиваться на `go-practice-01`; пустой список файлов здесь нормален.

Если путь другой, нажмите значок корзины у **этого терминала**, чтобы закрыть его, убедитесь, что открыта правильная папка, и создайте терминал заново. Закрытие терминала не удаляет файлы. Не пытайтесь исправить путь удалением папок.

### Шаг 2.4. Создайте модуль Go

**Команда для терминала, из папки `go-practice-01`:**

```text
go mod init example.com/go-practice-01
```

**Ожидаемое сообщение:**

```text
go: creating new go.mod: module example.com/go-practice-01
```

Слева появится **`go.mod`**. Нажмите на него: это текстовый файл с именем модуля и версией Go. **Модуль** объединяет пакеты проекта; подробности будут позже. В `go.mod` программу не пишем.

`example.com/go-practice-01` — учебное имя. Покупать домен, создавать сайт или регистрировать его не нужно. Команду выполняем **один раз для проекта**, не перед каждым запуском и не для каждой новой папки. Если сказано `go.mod already exists`, файл уже создан — второй раз команду не повторяем.

## 3. Создаём и запускаем первую программу

### Шаг 3.1. Создайте файл `main.go`

1. В левой панели VS Code нажмите правой кнопкой по папке `GO-PRACTICE-01`.
2. Выберите **New File / Создать файл**.
3. Напишите **`main.go`**, нажмите Enter. Откроется вкладка нового файла.
4. Скопируйте в неё **весь код ниже**, включая первую и последнюю строки.
5. Нажмите **Ctrl+S** в Windows/Linux или **Cmd+S** в macOS.

**Код для файла `main.go`, не для терминала:**

```go
package main

import "fmt"

func main() {
	fmt.Println("Привет! Это моя первая программа на Go.")
}
```

Полный файл для сверки: [пример `hello/main.go`](examples/hello/main.go). Не вставляйте слово `go`, которым может быть подписан блок, и тройные обратные кавычки из Markdown.

В папке должны быть два файла:

```text
go-practice-01/
├── go.mod
└── main.go
```

Важны точное имя `main.go`, расширение `.go` и сохранение файла. `main.go.txt` — другое имя. При создании через **New File** в VS Code задайте имя целиком.

### Шаг 3.2. Дождитесь настройки подсказок

При первом открытии `.go`-файла расширение может предложить установить инструменты. Согласитесь на установку **`gopls`** через предложение расширения Go. Если предложения нет, ничего дополнительно нажимать не требуется; при необходимости инструменты доступны через **View → Command Palette → Go: Install/Update Tools**.

`gopls` отвечает за подсказки редактора. Если установка не проходит, покажите текст ошибки преподавателю. Не скачивайте инструменты со случайных сайтов и не отключайте проверку сертификатов. Уже установленный Go позволяет выполнить следующий шаг и без подсказок.

### Шаг 3.3. Запустите код

Переключитесь **в нижний терминал**, не в файл. Убедитесь, что команда `pwd` по-прежнему показывает `go-practice-01`.

**Команда для терминала:**

```text
go run .
```

После команды нажмите Enter. Первый запуск может сопровождаться ожиданием сборки.

**Ожидаемый результат:**

```text
Привет! Это моя первая программа на Go.
```

`go run` собирает и запускает код, а точка `.` означает пакет в текущей папке. Также можно запустить один файл командой `go run main.go`, но основной способ здесь — `go run .`.

**Проверьте сами:** измените текст между кавычками, сохраните файл и снова выполните `go run .`. В терминале должен появиться **новый** текст. Простое изменение файла без запуска ничего в терминале не обновляет.

### Что означает написанный код

| Строка или знак | Объяснение для этой программы |
|---|---|
| `package main` | Обозначает пакет исполняемой программы |
| `import "fmt"` | Подключает стандартный пакет для форматированного ввода и вывода |
| `func main()` | Объявляет функцию `main`, с которой начинается наш код |
| `{` и `}` | Ограничивают тело функции; должны образовывать пару |
| `fmt.Println(...)` | Выводит значение в терминал и переводит строку |
| `"..."` | Обозначает строку текста |

`fmt` уже входит в Go SDK. Скачивать его отдельно не нужно. Регистр символов важен: `Println` и `println` — не одно имя.

## 4. Собираем исполняемый файл

Команды ниже выполняются **в терминале проекта**. Выберите только свой вариант.

**Windows / PowerShell:**

```powershell
go build -o hello.exe .
.\hello.exe
```

**macOS / Linux:**

```bash
go build -o hello .
./hello
```

Выполняйте строки по очереди. Первая создаёт файл `hello.exe` или `hello`; успешная сборка обычно не печатает сообщений. Вторая запускает созданный файл и должна вывести ваше приветствие. Не открывайте исполняемый файл как текст в редакторе.

`-o` задаёт имя результата сборки. `go run` удобен во время разработки, а `go build` позволяет отдельно получить исполняемый файл. Для запуска этой собранной программы редактор не нужен.

**Небольшой опыт:** снова измените текст в `main.go` и сохраните его. Запустите **только** `hello.exe` или `hello` второй строкой: увидите старое сообщение. Повторите `go build`, затем запуск — сообщение обновится. Уже собранный файл сам себя не пересобирает.

**Отформатируйте исходный код:**

```text
go fmt ./...
```

`./...` означает пакеты текущего модуля и его подпапок. Команда приводит оформление Go-кода к единому виду; отсутствие вывода означает, что менять было нечего.

На этом **задание 1 — первая программа** выполнено. `main.go` сохраняем: следующие эксперименты будут в другом файле.

## 5. Разбираемся с базовым синтаксисом

### Шаг 5.1. Создайте отдельную программу для экспериментов

Не размещайте несколько файлов с `func main()` в одной папке.

1. В левой панели нажмите правой кнопкой по `GO-PRACTICE-01` → **New Folder / Создать папку**. Назовите её **`cmd`**.
2. Нажмите правой кнопкой по `cmd` → **New Folder**, назовите вложенную папку **`experiments`**.
3. Нажмите правой кнопкой по `experiments` → **New File**, назовите файл **`main.go`**.

`cmd` — обычное имя папки для отдельных запускаемых программ. Это не новая программа и не специальная команда. Новый `go.mod` в ней **не создаём**.

Теперь первый `main.go` в корне и новый `cmd/experiments/main.go` — разные файлы:

```text
go-practice-01/
├── go.mod
├── main.go
└── cmd/
    └── experiments/
        └── main.go
```

### Шаг 5.2. Вставьте небольшой пример

**Код для `cmd/experiments/main.go`:**

```go
package main

import "fmt"

func main() {
	const language = "Go"
	var name string = "Ирина"
	completed := 1
	var ready bool = true
	var hours float64 = 1.5

	fmt.Println("Изучаем", language)
	fmt.Printf("Участник: %s\n", name)
	fmt.Printf("Выполнено: %d\n", completed)
	fmt.Printf("Готов продолжать: %t\n", ready)
	fmt.Printf("Продолжительность: %.1f часа\n", hours)

	completed = 2
	fmt.Printf("После изменения: %d\n", completed)
}
```

Сохраните файл. **В терминале оставайтесь в `go-practice-01`** и выполните:

```text
go run ./cmd/experiments
```

**Ожидаемый результат:**

```text
Изучаем Go
Участник: Ирина
Выполнено: 1
Готов продолжать: true
Продолжительность: 1.5 часа
После изменения: 2
```

В отличие от `go run .`, эта команда запускает программу из указанной подпапки. Открытая вкладка файла **не определяет**, что запустит терминал: это определяется командой и текущей папкой.

### Шаг 5.3. Измените значения и объясните результат

| Конструкция | Для чего используем |
|---|---|
| `var name string = "Ирина"` | Объявляем строковую переменную и задаём значение |
| `completed := 1` | Кратко объявляем переменную внутри функции; тип определяется по значению |
| `completed = 2` | Изменяем значение уже объявленной переменной |
| `const language = "Go"` | Объявляем константу; далее присвоить ей другое значение нельзя |
| `int`, `float64`, `bool`, `string` | Целое число, дробное число, логическое значение, строка |
| `fmt.Println` | Вывод с переводом строки |
| `fmt.Printf` | Вывод по строке формата |
| `%s`, `%d`, `%t`, `%.1f` | Места для строки, целого, логического и дробного значения |
| `\n` | Перевод строки в строке формата |

Измените имя и продолжительность, сохраните и запустите программу снова. Используйте вымышленные данные. Затем объясните соседу разницу между `:=` и `=`.

Более подробные примеры — **[синтаксис, арифметика и безопасный ввод](syntax-and-input.md)**. Там сохранены нулевые значения, комментарии, деление, преобразования типов и разбор `fmt.Scan`. Этот материал используем для конвертера; читать всю спецификацию Go сейчас не требуется.

### Шаг 5.4. Выполните карточку участника

Перейдите к **[заданию 2 — карточка участника](assignments.md#задание-2-карточка-участника-курса)**. Там показано, как создать файл `cmd/card/main.go`, что написать самостоятельно и как проверить результат. Затем вернитесь к следующему разделу.

## 6. Публикуем проект на GitHub

До этого момента все файлы находились **только на вашем компьютере**. Теперь будем сохранять историю с помощью **Git** и размещать проект на сайте **GitHub** — это разные инструменты.

Выполните **[первую публикацию проекта: установка Git, аккаунт, коммит и GitHub](../../docs/first-project-github.md)**. Инструкция начинается с установки Git и не предполагает, что вы уже умеете им пользоваться.

Используем тот же проект **`go-practice-01`**, с которым работали выше. Не создаём второй пустой Go-проект, не копируем работу в репозиторий преподавателя и не публикуем исполняемые файлы.

**Проверка результата:** в браузере открывается ваш репозиторий, видны `main.go`, `go.mod` и `README.md`, а после следующего изменения и отправки — новый коммит.

## 8. Если что-то не получается

| Что видите | Что проверить и сделать |
|---|---|
| `go` не найден | Вернитесь к установке, перезапустите VS Code после неё; расширение само по себе не устанавливает Go SDK |
| `go.mod file not found` | Выполните `pwd` и `ls`; нужна папка `go-practice-01` с файлом `go.mod` |
| `go.mod already exists` | Модуль уже создан; продолжайте со следующего шага |
| `no Go files` | Сохранён ли нужный `main.go`; верны ли текущая папка и путь в команде |
| `main redeclared` | Две функции `main` оказались в одной папке; сверяйте дерево проекта, не удаляйте первую программу |
| `expected 'package'` | В файл попала команда терминала, разметка или другой текст перед `package main` |
| `declared and not used` | Локальная переменная объявлена, но не используется: выведите её или исправьте код по смыслу |
| `imported and not used` | Пакет подключён, но его функции не используются |
| `no new variables on left side of :=` | Для изменения уже существующего значения требуется `=`, а не повторное объявление |
| `cannot use ... as ...` | Не совпадают типы; посмотрите пример явного преобразования |
| В выводе есть `%!` | Формат `Printf` не соответствует типу аргумента |
| Курсор ждёт, результата нет | Программа с `fmt.Scan` ожидает число: введите его в терминале и нажмите Enter |
| Не удаётся ввести новую команду | Запущенная программа ещё ждёт ввод; завершите ввод или остановите её **Ctrl+C** |
| Выводится старый текст | Сохраните нужный файл; для исполняемого файла повторите сборку |
| Ошибка Git или публикации | Используйте [таблицу ошибок Git](../../docs/first-project-github.md#если-что-то-не-получилось) |

Ошибка — это информация для поиска причины. Сначала прочитайте имя файла, номер строки и сообщение. Не исправляйте проблему случайным удалением кода.

## 9. Проверка и сдача

Из терминала **папки `go-practice-01`** выполните:

```text
go fmt ./...
go build ./...
```

Вторая команда проверяет сборку пакетов проекта. Если в проекте пока только одна исполняемая программа, она также может создать файл `go-practice-01` или `go-practice-01.exe`; наш шаблон `.gitignore` исключает его из Git. Для создания файла с выбранным именем используйте отдельный `go build -o ...`, как в разделе 4.

- [ ] Задание 1 запускается через `go run .` и как отдельно собранный файл.
- [ ] Задание 2 использует константу, переменные разных типов и форматированный вывод.
- [ ] Задание 3 проходит все семь проверок конвертера.

- [ ] В README есть описание, версии инструментов и команды запуска выполненных программ.
