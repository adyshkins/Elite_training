# Задания практической работы № 5

[Пошаговая методичка](README.md) · [Стартовые файлы](starter/README.md) · [Референсное решение](examples/README.md)

## Обязательная часть (90 минут + завершение дома)

Работайте в **собственном проекте** `go-practice-01`; предыдущие команды `cmd/task-model` и `cmd/task-cli` оставьте без изменений.

1. Добавьте пакеты `internal/tasks` и `internal/persistence`, отдельную команду `cmd/task-cli-json`. Исправьте путь импорта только если ваш `module` отличается от примера.
2. Реализуйте `Load`: отсутствующий файл → пустое состояние с `next_id=1`; некорректный файл → информативная ошибка и **никакого сброса данных**.
3. Реализуйте `Save` с JSON-тегами и промежуточным файлом. Сохраняйте и счётчик `next_id`, и задачи.
4. Продемонстрируйте четыре команды CRUD, корректную обработку ввода и сохранение после каждого успешного изменения.
5. Запустите `go test ./...`, `go vet ./...`, `go build ./...`.
6. Дополните личный `README.md` командами запуска и описанием `TASKS_FILE`; добавьте путь JSON-файла в `.gitignore`, опубликуйте новый коммит.

## Контрольный сценарий

| № | Действие | Ожидается |
|---:|---|---|
| 1 | Первый запуск, файла ещё нет | Пустой список, ошибки нет |
| 2 | Добавить «Изучить Go», приоритет 2 | ID=1, статус `new` |
| 3 | Добавить «Написать API», приоритет 3 | ID=2 |
| 4 | Завершить ID=1 | Статус `done`, запись в JSON |
| 5 | Завершить программу и открыть заново | Обе задачи и статус сохранились |
| 6 | Удалить ID=1, завершить программу | В JSON остаётся ID=2 |
| 7 | Перезапустить и добавить новую задачу | Новый ID=3, не 1 |
| 8 | Ввести пустое название или приоритет 4 | Ошибка, счётчик не изменился |
| 9 | Ввести нечисловой ID и несуществующий ID | Программа не аварийно завершается |
| 10 | Вручную заменить файл строкой `{oops` и запустить | Сообщение об ошибке, файл не затёрт |
| 11 | Удалить повреждённый файл (сделав его копию) | Следующий запуск начинается с пустого состояния |
| 12 | Выполнить `go test ./...` | Все тесты пройдены |

**Внимание:** в шагах 10–11 используйте **учебный JSON** и сделайте копию перед намеренным повреждением. Не подставляйте пути к реальным данным.

## Самостоятельные задания

- Дополните таблицу `TestLoadScenarios` кейсами: недопустимый статус, приоритет 0, повторный ID, `next_id` не больше максимального ID, пустое название. Проверяйте `errors.Is(err, tasks.ErrInvalid)` там, где это уместно.
- Напишите тест, который проверяет независимость списка `List()` от внутреннего среза.
- Опишите в личном README, почему два одновременно работающих экземпляра консольного приложения могут перезаписать результаты друг друга.
- **По желанию:** создайте учебную ветку `practice-05-experiment`, внесите небольшое изменение, сделайте коммит и объедините его с основной веткой. Не используйте `--force` и не удаляйте чужую историю.

## Критерии

- [ ] Код разделён по пакетам; создан **один модуль**, а импорты корректны.
- [ ] JSON содержит задачи и `next_id`; ID не повторяются после удаления/перезапуска.
- [ ] Не существующий файл и испорченный JSON обрабатываются по-разному.
- [ ] При проблеме сохранения выводится ошибка; неправильный файл не перезаписывается автоматически.
- [ ] CRUD работает с корректными и некорректными аргументами.
- [ ] Тесты проходят, `go vet` и `go build` без ошибок.
- [ ] В репозитории есть понятный README, настройки `.gitignore` и новый коммит.
- [ ] Студент может объяснить код без чтения по строкам.

**На защиту:** ссылка на личный GitHub, запуск программы до и после перезапуска, тесты и вывод `git log -3 --oneline`. Готовое решение преподавателя в качестве собственного не сдаётся.
