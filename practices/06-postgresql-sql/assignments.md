# Задания практической работы № 6

[← Методичка](README.md) · [SQL-схема](sql/01_schema.sql) · [Проверки ограничений](negative-tests.md)

## Обязательная часть

1. Подключитесь к **отдельной учебной** базе `tasks_lab` в PostgreSQL 17+ через Docker Compose, `psql` или pgAdmin.
2. Выполните `sql/01_schema.sql`, объясните связь `projects.id → tasks.project_id`, ограничения `PRIMARY KEY`, `FOREIGN KEY`, `NOT NULL`, `UNIQUE`, `CHECK`.
3. Заполните БД через `sql/02_seed.sql`, убедитесь, что есть **2 проекта и 4 задачи**.
4. Выполните `sql/03_select.sql`; разберите `SELECT`, `WHERE`, `ORDER BY`, `JOIN`, `LEFT JOIN`.
5. Выполните `sql/04_mutations.sql` (один раз после `02_seed.sql`); покажите результат `INSERT`, `UPDATE`, `DELETE`.
6. Выполните `sql/05_verify.sql` и `sql/06_assert_constraints.sql` — оба скрипта должны завершиться `NOTICE: OK` без ошибок. Второй проверяет пять ограничений и отсутствие нежелательных изменений.
7. По отдельности проверьте пять ожидаемых ошибок из [`negative-tests.md`](negative-tests.md). Объясните причину каждой.
8. Сохраните собственные SQL-файлы (не только результат в терминале) и обновите личный README, опубликуйте коммит.

## Проверочный сценарий

| № | Действие | Ожидаемый результат |
|---:|---|---|
| 1 | Посмотреть таблицы через `\dt` | `projects`, `tasks` |
| 2 | `SELECT COUNT(*) FROM projects` после seed | 2 |
| 3 | `SELECT COUNT(*) FROM tasks` после seed | 4 |
| 4 | Выбрать новые задачи с приоритетом ≥ 2 | «Написать API» (3), «Изучить Go» (2) |
| 5 | Объединить `tasks` и `projects` | У каждой задачи корректное название проекта |
| 6 | Выполнить `04_mutations.sql` | 2 проекта и 4 задачи, нет «Временной задачи» |
| 7 | `05_verify.sql` | Сообщение `NOTICE: OK` |
| 8 | Вставить задачу с `project_id=999999` | Ошибка внешнего ключа, строка не создана |
| 9 | Вставить приоритет 9 | Ошибка `CHECK`, строка не создана |
| 10 | Удалить проект с задачами | Ошибка `RESTRICT`, данные на месте |

**Повторяемость:** если захотите повторить запросы, выполните `02_seed.sql`, затем `03_select.sql` → `04_mutations.sql` → `05_verify.sql`. Повторный `01_schema.sql` не нужен.

## Самостоятельная часть

- Напишите `SELECT` всех незавершённых задач выбранного проекта, отсортированных по приоритету от 3 к 1 (при равенстве — по ID).
- Выведите название каждого проекта и число его задач, включая проекты с нулём задач. Объясните `COUNT(t.id)` и `LEFT JOIN`.
- Добавьте **третью** запись проекта с названием «Аналитика», не добавляя задачи. Проверьте, что запрос с `LEFT JOIN` вернул для неё 0. Для возврата к базовому сценарию запустите `02_seed.sql`.
- Создайте `UPDATE` по **ID**, а не по заголовку, и объясните, почему ID надёжнее: названия задач не объявлены уникальными.
- **Дополнительно:** выполните `BEGIN`, вставку одной тестовой задачи, `ROLLBACK` и проверьте, что количество задач не изменилось.
